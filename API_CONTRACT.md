# API для сайта Frame

Фронтенд готов в `frontend/`. Бэкенд на FastAPI реализуешь самостоятельно.
Никаких Telegram file_id: оригиналы теперь хранит бэкенд на диске или в объектном хранилище.

## Запуск сайта

Из корня проекта:

```powershell
python -m http.server 5500 --bind 127.0.0.1 --directory frontend
```

Открыть http://localhost:5500. Не открывай HTML через `file://`.
Сервер раздаёт только папку frontend, а не корневой `.env`.
В кнопке «Подключение» укажи адрес API. По умолчанию: `http://localhost:8000`.
Адрес сохраняется в localStorage. Маршруты ниже прибавляются к этому адресу.
Для интерфейса не нужны Node.js и сборка. Шрифт загружается с Google Fonts;
без интернета используется системный шрифт.

## 1. POST /api/photos — добавить фотографию

Вход: `multipart/form-data`, поле `file` — один файл.
FastAPI: параметр `file: UploadFile = File(...)`.
Для приёма multipart понадобится пакет `python-multipart`.

Действия:

1. Проверить размер (до 10 * 1024 * 1024 байт) и декодировать изображение.
   Разрешены JPEG, PNG, WEBP. Проверять реальные байты, а не только MIME от браузера.
2. Сгенерировать UUID, сохранить оригинал под своим безопасным именем.
   Не использовать пользовательский filename как путь на диске.
3. Получить embedding той же CLIP-моделью, что используется для поиска.
4. Записать point в Qdrant: UUID, vector (512 чисел), payload с filename и image_url
   либо ключом сохранённого файла. Метрика коллекции — Cosine.
5. Ответить успехом после записи файла и point. Если запись Qdrant не удалась,
   убрать созданный файл или обеспечить последующую очистку.

Ответ: HTTP 201, JSON:

```json
{
  "id": "5f518b29-3ba6-45ba-a623-f31d016f3482",
  "filename": "dog.jpg",
  "image_url": "/api/photos/5f518b29-3ba6-45ba-a623-f31d016f3482/image"
}
```

`id` — строка. Успешный ответ означает, что фото уже доступно поиску.
Каждая загрузка может создавать отдельную запись; автоматической защиты от дублей
в интерфейсе нет. Отмена запроса в браузере не гарантирует отмены записи на сервере.

## 2. POST /api/search — найти до трёх похожих

Вход: `multipart/form-data`:

- `file` — один файл (те же правила проверки).
- `limit` — поле формы, строка `"3"`; FastAPI принимает как целое через `Form`.
  Можно ограничить допустимое значение диапазоном 1–3, значение по умолчанию — 3.

Сигнатура для ориентира: `async def search(file: UploadFile = File(...), limit: int = Form(3))`.

Действия: изображение → CLIP → `query_points(..., limit=limit, with_payload=True)`.
Фото-запрос не добавлять в Qdrant. Временный файл после поиска удалить.
Результаты вернуть по убыванию cosine similarity, максимум `limit` элементов.

Ответ: HTTP 200, JSON:

```json
{
  "matches": [
    {
      "id": "5f518b29-3ba6-45ba-a623-f31d016f3482",
      "filename": "dog.jpg",
      "score": 0.893,
      "image_url": "/api/photos/5f518b29-3ba6-45ba-a623-f31d016f3482/image"
    }
  ]
}
```

`score` — конечное JSON-число, не строка и не процент. Если база пуста,
вернуть HTTP 200 и `{"matches": []}`. Коллекцию создай при старте приложения
или обработай её отсутствие как пустую базу. Не создавай модель на каждый запрос.
Синхронные CLIP/Qdrant-вызовы внутри async-обработчика выноси в рабочий поток.

## 3. GET /api/photos/{photo_id}/image — отдать оригинал

Ответ HTTP 200 — байты изображения с правильным Content-Type
(`image/jpeg`, `image/png`, `image/webp`), например через `FileResponse`.
Для неизвестного UUID — HTTP 404. Фронтенд использует этот URL в `<img>`
и открывает оригинал по клику. Для этого учебного проекта URL доступен без авторизации.

Можно вместо отдельного обработчика раздавать картинки через StaticFiles:
тогда возвращай соответствующий `image_url`, например `/media/<uuid>.jpg`.
Везде используй URL, а не локальный путь вида `D:\\photos\\dog.jpg`.
Относительные URL вида `/api/...` разрешаются относительно origin API.

## Ошибки

JSON: `{"detail": "Понятное описание ошибки"}`.

- 413 — превышен размер файла.
- 415 — неподдерживаемый формат.
- 422 — повреждённое изображение / неверные параметры.
- 503 — недоступен Qdrant или модель.
- 500 — непредвиденная ошибка (подробности в логах сервера).

Стандартный массив `detail` от FastAPI для ошибок валидации тоже поддерживается.
Фронтенд ждёт ответ до 120 секунд. CORS-заголовки должны присутствовать и на ошибках.

## CORS

Фронт и API работают на разных портах. Разреши в FastAPI CORSMiddleware:

```text
allow_origins = ["http://localhost:5500", "http://127.0.0.1:5500"]
allow_methods = ["GET", "POST"]
allow_headers = ["*"]
```

Cookie-авторизация не используется. Не прописывай Content-Type вручную в fetch:
браузер сам формирует multipart boundary.

## Что проверять

1. Без API: интерфейс позволяет выбрать фото и показывает ошибку соединения при отправке.
2. Добавить 3 разных фотографии: после каждого ответа 201 видно подтверждение.
3. Найти похожие: до 3 реальных картинок, filename, числовой score.
4. Поиск не меняет количество points.
5. Пустая база возвращает matches=[], сайт показывает пустой результат.
6. Текстовый файл и файл больше 10 МБ не отправляются с сайта.
7. Ошибки API отображаются, кнопка снова становится доступна.
8. При смене режима/файла старый ответ не подменяет новый результат.

Frontend smoke tests (Node.js, без установки пакетов):
`node --test frontend/tests/app.test.cjs`.

## Коллекции: подключённый фронтенд

- GET /api/collections возвращает {"collections": [{"id": "UUID", "name": "Название"}]}.
- POST /api/collections принимает JSON {"name": "Название"}, возвращает 201 и {"id": "UUID", "name": "Название"}.
- Фронт загружает список при открытии страницы и смене адреса API. Новая коллекция выбирается автоматически.
- POST /api/photos: multipart-поля photo и collection_name. Несмотря на имя, collection_name содержит UUID записи PostgreSQL — это фактическое имя поля текущего бэкенда. Загрузка без выбора блокируется.
- POST /api/search также принимает multipart-поля photo и collection_name (UUID). Фронт передаёт limit=3 в query string, как ожидает текущий сервер. Без выбранной коллекции поиск и загрузка блокируются.
- Поиск использует выбранную коллекцию. Получение оригинала на сервере пока обращается к test: следующий шаг — включить UUID коллекции в image_url и разрешать его через PostgreSQL в GET изображения.
- Для загрузки сервер должен разрешить UUID через PostgreSQL и передать collection.name в Qdrant. ID point должен совпадать с возвращаемым file_id.
